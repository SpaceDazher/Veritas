# S2-006M — автономная модельная подготовка корпуса

Общий маршрут автономного закрытия инженерных тикетов Stage 2 и границы
его verdict описаны в `tasks/S2_AUTONOMOUS_DELIVERY_PLAN.md`.

## Решение и граница

Владелец 2026-09-22 разрешил изменить рабочий план так, чтобы агент мог
продвигать проект без команды аннотаторов. S2-006M — отдельный маршрут
подготовки и исследования источников. Он не выдаёт `PASS_WITH_LIMITS` за
S2-006 и не изменяет `deriveVerdict`, frozen-схемы, полномочия или правило
человеческого принятия критических решений. Официальный S2-006 остаётся
`NEEDS_INPUT` до появления независимой разметки и HumanDecision.

Модель может самостоятельно читать предоставленные локальные материалы,
вычислять контрольные суммы, выделять кандидатов, проверять точность
транскрипции, искать внешние первичные источники и предлагать диагностические
цели. Всё это помечается `MODEL_ASSISTED_NOT_INDEPENDENT`. Модель не может
создать независимость количеством ролей, ключей, процессов или API-вызовов.

доступны модели, а источниковые права двух архивов указаны как `unknown`.

## Агентский протокол

1. Проверять SHA-256 входных архивов и не исполнять вложенные скрипты.
   Сырые транскрипты с неразрешёнными правами остаются локально; в Git
   допускаются только ID, метаданные, ссылки и агрегаты.
2. Считать upstream lineage по ID выпуска. Выбирать не более одного
   кандидата на пару `(episodeId, semanticTemplate)`; при равных условиях
   предпочитать STRICT/кандидата без `transcript_uncertain`. Флаги
   неопределённости сохранять, не стирать.
3. Для каждого утверждения разделять факт «говорящий произнёс» и
   проверку самого факта. Цитата из подкаста доказывает только первое.
   Внешние источники и модельный вывод хранить отдельно от gold labels.
4. Перед любой оценкой фиксировать входной hash, версию модели/prompt,
   стоимость и режим данных. Платный/API-вызов требует отдельного grant с
   лимитами task/campaign/day; при отсутствии grant оставлять
   `NOT_RUN_PROVIDER`. Не извлекать секреты из переписки или пакета.
5. Предложенные здесь диагностические затворы: 100% целостности входных
   архивов, 100% совпадений цитат после документированной нормализации,
   ноль дублей ID, не менее 20 различных пар выпуска и шаблона в
   кандидатном пуле, ноль утечек/private/authority violations. Эти
   агентские цели касаются только подготовки данных; числовые semantic
   thresholds исходного S2-006 остаются `NEEDS_INPUT`.
6. Публиковать только технические счётчики и source-review заметки.
   Precision, recall, F1, agreement, paired statistics и external validity
   без независимых labels получают `NOT_MEASURED`; verdict по S2-006 не
   меняется.

## Критерии завершения автономного этапа

- Индекс из предоставленных архивов воспроизводит 21 уникальную пару с
  истинным episode lineage и отмечает риски/неизвестные права.
- Каждая выбранная цитата найдена в соответствующем локальном транскрипте
  после точно описанной нормализации; несовпадение исключает кандидата.
- Три `NEEDS_SOURCE` из v0.5 имеют ссылки на первичные источники и
  модельные разборы без gold verdict и без автоматического повышения до
  `ACCEPT`.
- Никакой HumanDecision, grant, custody key или independent label не
  создаётся от имени отсутствующего человека; исходный S2-006 сообщает
  `NEEDS_INPUT`.
- `manifest:check`, `git diff --check` и штатные gate для затронутой
  поверхности проходят. Итог этапа — `MODEL_ASSISTED_INTAKE_COMPLETE`,
  если всё перечисленное подтверждено.

Следующий, отдельно версионируемый эксперимент с API-моделью может строить
гипотезы и сравнивать согласованность запусков на этом пуле. Он не превращает
их в независимую калибровку и не разрешает производственное применение.

## S2-006M-P1: пользовательский OpenRouter-пилот (2026-09-22)

Владелец отдельно разрешил отправку **коротких фрагментов** предоставленных
YouTube-подкастов в `poolside/laguna-s-2.1:free`, зная предупреждение Poolside:
бесплатные запросы и ответы могут использоваться для обучения. Это разрешение
относится только к диагностическому эксперименту S2-006M-P1, не к S2-006,
provider-grant, независимой разметке, публикации полных транскриптов или
production. Входы локальны; Git получает только агрегаты и digest, не цитаты,
ответы модели, API-ключи или полные запросы.

Пилот использует максимум 21 явно выбранный case, ровно один запрос на case,
фиксированную бесплатную модель без fallback и короткий quote+claim. Цель —
классифицировать, поддерживает ли цитата **атрибуцию утверждения спикеру**;
это не проверка истинности утверждения. Результат на каждом case —
`SUPPORTED | PARTIAL | NOT_SUPPORTED | UNCERTAIN | INVALID_RESPONSE | API_ERROR`,
с флагом необходимости внешней проверки. Никакие результаты не становятся
gold labels. Отдельный локальный файл хранит диагностические ответы для
просмотра владельцем; официальный verifier и `deriveVerdict` не вызываются.

Если API вернёт платную модель, невалидный ответ, лимит, сетевой сбой или
неподходящую форму данных, запуск отмечает отказ без ретрая. Проверка
транскриптов, endpoint/privacy и статус `NEEDS_INPUT` остаются видимыми.

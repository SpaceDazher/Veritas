## Статус

```text
engineeringStatus = BLOCKED_DEPENDENCY
assuranceStatus   = NOT_MEASURED
realAdapterStatus = NOT_RUN_REAL_ADAPTER
aMvpStatus        = NOT_RUN (A-MVP-01..07)
```

Инженерный слой закрыт и измерен: `test:s2-007` → exit 0 (338/338),
`test:s2-007-security-probes` → exit 0 (41/41), `s2-007:run` → exit 0
(118/118 ожиданий, 11/11 guards), `verify:s2-007-db-replay` → exit 0 на реальном
PostgreSQL 17.11, `typecheck`, `lint` и `build` → exit 0.

Открыт один пункт: `npm run verify:s2-007-dependencies` → exit 1
(`BLOCKED_DEPENDENCY`), потому что обязательный `verify:s2-002` падает на этом хосте.
Падение **предсуществующее**: чистый базовый коммит `f590d37` (без единого файла
S2-007) в отдельном worktree даёт ровно те же 6 падений.

Корень найден и воспроизведён эмпирически. Первая версия разбора («это не измеренный
escape») была **частично опровергнута** адверсарной проверкой; исправленный вывод:

* **Два** дефекта платформенного скоупинга в `s2-002-run.mjs`, а не один. Кроме
  необработанного `PLATFORM_UNSUPPORTED` от Windows-only пробы (`:186` — производится в
  одном месте, не обрабатывается нигде), **oracle** исключает
  `sandbox/fs-junction-escape` на не-Windows (`:95`), тогда как раннер её всё равно
  **выполняет** (`:182-184`): на Linux проба проходит (`match: true`), но oracle её не
  ждал — это и есть второе, независимое `trialCount=283/oracle=282`.
* Утечек секретов на этом хосте **не наблюдалось**: `1` — это отклонённая проба, других
  наблюдений нет. Каноническое Windows-измерение **не опровергнуто**: его digest
  совпадает, и выполненные Linux-наблюдения хешируются тем же digest — расходится
  Linux-*oracle*.
* **Главное: учёт отмены на не-Windows хосте ошибается в разрешающую сторону.**
  `listDescendants` вне Windows возвращает `[]` (`sandbox.mjs:213`), а ребёнок спавнится с
  `detached: false` (`:389`), поэтому группа процессов не сигналится и умирает только
  прямой потомок. Воспроизведено на production-адаптере: `cancel()` вернул
  `{terminated: true, survivors: 0, remainingProcessIds: []}` за 102 мс, пока **два внука
  продолжали работать**. То есть *включение* отклонённой пробы на этом хосте дало бы
  **ложный PASS**. Отказ платформы — единственное, что сейчас не даёт записи заявить
  свойство безопасности, которого у хоста нет.
* Сентинг `-1` дополнительно **fail-open** в основном гейте: `verify-s2-002.mjs`
  сравнивает через `value > limit`, поэтому `-1`, `-9999` и любой отрицательный
  magnitude проходят. Его ловит только `tests/identity/replay-runs.test.mjs`.

Итог для S2-007: dependency gate правильно остаётся красным, и **ослаблять Linux-счётчики —
неправильный фикс**: это стёрло бы единственный сигнал о том, что tier на этом хосте
недоказуем, и пропустило бы ложный PASS. Верное действие — переизмерить S2-002 на Windows.
Разбор, карта симптомов, четыре дефекта, воспроизведение и рекомендуемые изменения:
[S2-002-NON-WINDOWS-HOST-ANALYSIS.md](../decisions/S2-002-NON-WINDOWS-HOST-ANALYSIS.md).

Ничего в S2-002 из S2-007 не менялось: его счётчики, раннер, тесты, evidence и
frozen manifest принадлежат другому тикету, и ослаблять их ради зелёного
собственного gate — ровно то, что issue запрещает. Пока владелец не запишет решение,
dependency gate остаётся красным и статус выше `BLOCKED_DEPENDENCY` не поднимается.

Адверсарный ревью-проход нашёл и закрыл три реальных дефекта (fail-open на
отсутствующем grant — critical, `collect_result` без transition guard — high,
недостижимая ветка minor-version handshake — medium); подробности и регрессионные
тесты: [S2-007-EVALUATION-REPORT.md](../decisions/S2-007-EVALUATION-REPORT.md) §0.1.

## Граница ответственности

Veritas владеет TaskBrief, политикой, доской, бюджетным разрешением, evidence и
решениями. AgentOS исполняет разрешённый запуск через `veritas.execution/1.0.0`
и не становится вторым источником истины или органом одобрения. Veritas не
реализует произвольный shell runner и не выдаёт разрешение на реальную работу
агента. `DONE` достижим только через аутентифицированного человека или отдельно
разрешённый детерминированный gate.

## Что не доказано

- Реальных адаптеров нет: все запуски прошли через скриптованный test
  transport, поэтому каждая запись о границе исполнения — `NOT_RUN_REAL_ADAPTER`.
- `A-MVP-01..07` — `NOT_RUN`. Fixture/replay evidence не меняет `NOT_RUN`
  задним числом и никогда не превращается в `A-MVP PASS`.
- `assuranceStatus` = `NOT_MEASURED`: семантическая точность, человеческий
  review, реальные cost и latency не измерялись. Все метрики — инженерные
  прокси над инъецированными часами.
- Проверка шла на эфемерном podman-контейнере, а не на production-инстансе.
- Финальный acceptance-набор (`npm test`, `typecheck`, `lint`, `build`,
  `inventory:check`, `manifest:check`, `verify:clean-checkout`,
  `git diff --check`) целиком не запускался в этой итерации.

# Stage 2 / S2-008: R&D experiment cycle — the deterministic parallel track

## Purpose

Issue [#8](https://github.com/SpaceDazher/Veritas/issues/8) asks for an R&D
experiment cycle: a hypothesis is preregistered, seeds and a baseline are
frozen, a budget is reserved, trials run, a metric is measured, and the result
decides something. Read literally it also asks for **a campaign on a real
project, with real spend and the task quality of a live executor**. Veritas
has none of that and does not pretend to have it.

S2-008 builds the **deterministic parallel track**: the whole governance
surface of the cycle — preregistration, frozen baseline, seed freezing, budget
reservation, fail-closed decision, six negative probes, six negative controls,
a frozen expected-value table, two process-separated runs and a cross-process
replay — designed to run **offline against authored fixtures**. It is built to
prove the *decision rules* are load-bearing. It proves nothing about a real
campaign and it does not replace one. The ticket's own scope stays behind
[#45](https://github.com/SpaceDazher/Veritas/issues/45); see
*The ticket's own acceptance is not replaced by this track*.

### Four probe states, not two

`ProbeRecorder.result()` returns `pass` | `failed` | `broken` | `not_run`, and
the four mean different things:

- `failed` — a **discovered bypass**. The counter moved. A hard gate.
- `broken` — the probe's **control did not flip**. Nothing got through, so the
  counter must not move — and the probe must not pass either. The defence is
  **unproven**, which is a different state from a proven defence. The reason is
  recorded under the `control_flips: ` prefix so a reader can see why.
- `not_run` — the probe could not run: a missing dependency, an absent fixture,
  or a fixture that fails its own frozen contract. Never a pass, never counted,
  and the gate **exits 3 rather than 0**.
- `pass` — the only green state, and it requires the counter to be `0` **and**
  the control to have flipped.

### The six negative controls

`holdout_peek`, `seed_substitution`, `budget_opacity`, `label_substitution`,
`missing_evaluator`, `corrupted_data` — the frozen, closed set, no additions and
no omissions. Every control flipping is itself a hard gate. Measured in
`evidence/s2-008-controls.json`: `allFlipped = true`, `gate.ok = true`,
`notRun = []`, with the flips recorded as

```text
holdout_peek       ALLOW          -> VIOLATION
seed_substitution  ALLOW          -> VIOLATION
budget_opacity     ALLOW          -> VIOLATION
label_substitution ADMITTED       -> REFUSED   (CAUSAL_ASSERTION_UNSUPPORTED:CORRELATION_EVIDENCE)
missing_evaluator  ALLOW          -> VIOLATION
corrupted_data     no_findings    -> findings_non_empty  (in BOTH runs, digests equal)
```

`corrupted_data` is the A2 half that the comparator controls cannot reach: the
same corruption is injected into both runs, their digests are left equal, and
only the frozen table can produce the findings.

**The known limit, recorded rather than inherited.** The identical-wrong control
proves the table load-bearing only for the classes it corrupts. It must corrupt
at least one class per frozen category, and the comparison record must itemise
which classes were and were not covered. S2-007 notes the same limit of its own
control; it is not inherited unexamined.

## The rest of what the ticket requires

### Preregistration before the first run

The committed preregistration
(`evidence/s2-008/corpus/preregistration.json`, digest
`8fab7e83d472b7914b6e660dd956f6dc394589bcd4ab323162b6545dde7fe479`) publishes,
before trial one: the hypothesis card, the metric (`case_agreement_rate`,
ratio, `HIGHER_IS_BETTER`), the frozen baseline, the seed rule
(`kind: FIXED_LIST`, `seeds: [101, 202, 303, 404, 505]`,
`best_seed_selection: FORBIDDEN`), the stopping rule (`kind: FIXED_TRIALS`,
`max_trials: 4`, and an explicit `on_infra:
RECONCILIATION_REQUIRED_NOT_RETRY_NOT_ZERO`), the budget reservation (8
`trial_runs`, `trial_timeout_ms`, an `expires_at`), the holdout access policy
(`one_shot: true`, `max_opens: 1`, `reads_before_data: true`, an unseal digest),
the multiplicity rule, the noise rule (Wilson, 0.95, 2000 bootstrap samples,
fixed bootstrap seed) and `inference_mode: ASSOCIATIONAL`.

`assertPreregisteredBeforeRun` proves the ordering and `assertTableFrozen` pins
the in-code expected table (`9aad76e1b0f8c6f5…`) against the committed
preregistration before trial one. That mechanism, not good intentions, is what
stops a run from editing the expectation to match its result.

### A hypothesis edited after a result is a NEW document type

Not an edit of the preregistration. `createAmendment` produces a document of
kind `AMENDMENT` carrying its own reason and a new `card_id`, and
`assertAmendmentNotDecisionBasis` refuses it as a decision basis while still
admitting it as a journalled record. The property being proved is a **mutation
that must throw**: a post-result `test_design` edit keeps the same `card_id` and
still satisfies the frozen schema, so only `preregistrationDigest` can catch it.

### Negative, null and infra results are first-class outcomes

`RESEARCH_OUTCOMES` keeps five apart, and none of them is a zero:

- `NEGATIVE` — a measurement that clears the noise band the other way;
- `NULL` — a measurement **inside** the band. A real answer, not a negative
  one. Merging the two is how "no effect" becomes "no measurement" and back;
- `INFRA` — a definite, observed failure of the machinery. It does **not** open
  a reconciliation: a definite failure is not an unknown effect;
- `UNRESOLVED` — an effect nobody observed;
- `POSITIVE` — the only outcome that can support a positive claim.

A trial cannot be deleted from the expected-value table by failing to run: a
`SKIPPED`, `UNRESOLVED`, `INFRA_ERROR` or `NOT_MEASURED` trial has a row, and its
row says `VIOLATION`. In the committed run, trial 4 is exactly that case:
`status=INFRA_ERROR`, `table=INFRA`, `derived=INFRA`, `agrees=true`,
`observed=null`, `reason=MEASUREMENT_ABSENT`.

### Wall-clock latency is measured, but the decision follows the frozen rule

`latencyRecorded` records latency samples through the existing
`percentileBootstrapInterval` with the preregistered seed and sample count, and
every returned sample block carries `decides: false`. `runner.mjs` refuses a
latency block that claims otherwise, so "latency never decides" is a guard and
not a convention. The run output asserts `latency_decides=false`. The
comparator never reads the clock.

The decision follows `decisionFromInterval`, pure arithmetic over constants the
preregistration published before trial one: a non-`RESOLVED` status decides
nothing; an interval entirely inside the band is `NULL`; an interval that
straddles the null but leaves the band is `UNRESOLVED`; the multiplicity
correction runs over the **declared** family, never over "the comparisons that
happened to be significant". "Not significant at the corrected level" is
`UNRESOLVED`, not `NULL`.

### An interrupted run or an expired reservation is a reconciliation

Not a blind retry and not a silent zero. `runner.mjs` contains **no retry path at
all**. An `UNRESOLVED` trial, a timeout, or a reservation whose `expires_at` has
passed opens a `RECONCILIATION_REQUIRED` with an explicit decider kind, and the
unexecuted trials are recorded as `SKIPPED` with the code that refused them. A
refused run still produces a record — `status` is `REFUSED` or
`RECONCILIATION_REQUIRED` — because a refusal that throws away its evidence is
worse than one that records it. The cross-process replay exercises this: phase 1
is `SIGKILL`ed, phase 2 reopens the same ledger, `chain_verified = true` and the
reconciliation row is present.

Exit codes are deliberately distinct and are never averaged:

not check" and "I checked and it failed" are the two states a fake green is
made of.

### Two REAL defects the repair found in the pipeline itself

1. **The holdout ACCESS row was being erased.** `scripts/s2-008-run.mjs` opened
   the one-shot holdout and then called `runDeterministicRun`, whose first act is
   `purgeRegistry(registry)` — so the run's own journal never contained the
   `ACCESS` row its record named (`holdout_access.access_record_id =
   rec-8d45f8990001`, absent from `ledger.record_kinds`). This is why
   `EXPECTED_LEDGER_SHAPE` declared one `ACCESS` row and the delivered run always
   had zero: the frozen shape could not hold. The purge now happens in the run
   script **before** the open, and the engine is told the purge was performed —
   and PROVES it rather than believing it: `purgeForThisRun` refuses with
   `PURGE_NOT_PERFORMED` when a row the engine writes survived. After the repair
   the delivered run's journal is
   `["ACCESS","PREREGISTRATION_RECORDED","BUDGET_RESERVATION","BUDGET_SPEND","TRIAL_RESULT", …]`
   and `ledger_shape_ok = true`.
2. **`assertPartitionAccess` could not make a decision.** The `ACCESS` payload
   the ledger commits carried no `released_actor_kinds`, and `readCorpus` looked
   the row up by `payload.access_record_id`, which no envelope carries — so the
   guard always scored a synthetic fallback with no release list and failed
   closed for the wrong reason. The payload now carries the release list, the
   lookup is by `record_id`, and probe P1 proves both sides: an unreleased actor
   kind is refused with `HOLDOUT_ACCESS_NOT_RELEASED` and a **released** one is
   admitted. Before the repair that rule had zero attack coverage.
